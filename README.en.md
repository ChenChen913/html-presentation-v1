# html-presentation

> Single-file HTML presentation template library — 20 templates × 10 fully-worked slides each, zero dependencies, works offline.

A slide template repository built for both AI Skills and human users: no tooling required — open any template in a browser and present. Every template ships as a complete, layout-verified demo deck, so turning it into your own presentation is just a matter of replacing the text.

---

## ✨ Features

- **Single file, zero dependencies** — All CSS, JS, charts and code highlighting are inlined. No CDN, no web fonts, no icon libraries; double-click and it runs even offline.
- **20 templates × 10 slides** — Each template demonstrates 10 real layouts (cover, agenda, data, chart, table, timeline, quote, closing…), making them reliable references for density and rhythm.
- **Three design families in one repo** — All 12 glass templates share the same *Glassmorphism* DNA (saturated gradients, ambient light, frosted glass, humanist typography): 8 classics (01-08) plus 4 new color worlds (09-12).
- **Keynote editions (13-18)** — Apple-keynote style fullscreen minimalism: glass light-and-shadow with 3D glass cubes, backdrop-filter frost, prism dispersion and a looping soft sweep; three light editions (cream autumn / morning-mist celadon / glacier mist) and three dark editions (dark stage / deep-space blue / aurora night-flight).
- **Gallery & Scroll editions (19-20)** — 19 Gallery Album: museum-catalog editorial typography with left-aligned asymmetric grids, oversized serif titles, magazine-style corner details and glass frames refracting oversized characters; 20 Eastern Scroll: ink-green & gilded gold, center-axis vertical writing, chapter numerals (壹贰叁肆伍), glass moon/screens and vermilion seals — for exhibition catalogs and Eastern aesthetics.
- **One unified slide engine** — Keyboard, touch swipe, buttons, URL hash deep links and fullscreen behave identically across all templates; 13-20 add mouse-wheel navigation.
- **Built-in guardrails** — The repo includes layout rules and an avoid-list, so AI agents generating from these docs reliably dodge the classic "AI slide" pitfalls: purple gradients, emoji bullets, truncated content.
- **Ready to use as a Skill** — Ships with a standard `SKILL.md`; drop the repo into any Skill-capable AI environment.

## 🚀 Quick Start

```bash
git clone https://github.com/your-name/html-presentation.git
cd html-presentation/references/templates
# Open any templateXX.html in your browser — that's it.
```

**Make it yours**: duplicate a template → keep all CSS and the `<script>` engine at the bottom → replace text slide by slide → save. Done.

## 🎨 Design System

**The standard 10-slide arc** (shared by all 20 templates): Cover → Agenda → Problem → Core idea → Key data → Comparison → Roadmap → Deep dive → Summary → Closing (13-18 use a keynote variation, 19 an album variation and 20 a scroll variation: page types are reorganized per family, count unchanged).

**Density budget**: max 5 bullets per slide, max 80 CJK characters of body copy, titles ≤14 characters and always on a single line; overloaded content must be split across slides — never shrink the font to squeeze things in. This is the fundamental guarantee against truncated content.

**Zero-dependency trio**: charts are hand-drawn inline SVG; code highlighting is hand-tagged `<span>`s; icons are inline SVG geometry; fonts fall back through local stacks (glass 01-12: LXGW WenKai → Kaiti → serif; keynote 13-18: PingFang SC → YaHei → sans-serif; album 19: Songti SC → Noto Serif SC → serif; scroll 20: Kaiti SC → STKaiti → KaiTi → serif).

**One idea per slide**, and a single accent color across the whole deck.

Full rules: [references/LAYOUT_RULES.md](references/LAYOUT_RULES.md) and [references/AVOID_LIST.md](references/AVOID_LIST.md).

## 🤖 Using as a Skill

The `SKILL.md` at the repository root is a standard Skill manifest. Once installed in a Skill-capable AI environment, the agent triggers whenever the user asks for "a deck / slides / a presentation": pick a template → duplicate it as the draft → rewrite content slide by slide → run the pre-flight checks → deliver. The rule files (layout / avoid-list / catalog) are read during generation to enforce output quality.

## 🛠 Extending

- **Content edits**: touch only text and numbers — never the CSS class structure or the engine.
- **Recolor**: edit the `:root` CSS variables only (dual-theme templates have a dark block too).
- **Add slides**: duplicate the structurally closest slide; progress bar and counter adapt automatically.
- **New templates**: fork the closest family exemplar, follow both rule documents, and run the self-check in section 9 of the avoid-list before shipping.
